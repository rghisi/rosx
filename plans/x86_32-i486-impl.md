## M3 — static ISA audit (`cargo xtask check-isa x86_32`, committed with this log)

- New `xtask/src/check_isa.rs`: allow-list classifier over `objdump -d` text.
  Non-instruction lines are skipped by the `addr: ⇥ bytes ⇥ text` shape;
  `lock/rep*/data16/addr16/bnd` prefixes are stripped before the check;
  rejection is anything outside the 386/486 allow-list — the named list of the
  plan plus *any* x87/SSE/MMX or later mnemonic by construction.
- One byte-sensitive rule: objdump decodes `f3 0f bc` as `tzcnt`; that is the
  legacy `rep bsf` fallback LLVM emits without BMI, which executes as `bsf`
  (prefix ignored) on a 486. Allowed only with the `f3` byte prefix; `lzcnt`
  has no such equivalent and is always rejected.
- `nopw`/`nopl` (0F 1F multi-byte padding, availability P6+) are deliberately
  *not* in the allow-list: this tree pads with `0x90` only (measured: all
  nops in kernel + ELFs are `90`), and any future switch to hinted-nop
  padding must trip the gate loudly for a human decision.
- `movsd` is allow-listed as the 386 string move; objdump prints the SSE2
  scalar-double form identically, and the M1 feature pin is what guarantees
  only the string form exists. Audit limitation recorded here, not in code.
- Unit tests: header/padding skip, named-mnemonic rejection, x87/SSE rejection,
  the kernel workhorse list (lock cmpxchg/xadd/decl, tzcnt+f3, pause, rep
  movsl, iret, lgdtl…), tzcnt-without-f3 rejection, lzcnt rejection,
  occurrence aggregation. Green: 8/8 (`cargo test -p xtask`).
  Test-driven fixes during bring-up: AT&T `setcc` is 4 *or* 5 characters
  (`seta`/`setae`), and `movw`/`lgdtl` joined the allow-list — both misses
  caught by the on-tree audit before commit.
- CI: step `ISA audit (486 baseline)` added to the `build-x86_32` job after
  `cargo xtask build x86_32`; the x86_64 job is untouched and the subcommand
  refuses non-x86_32 arches with exit 2.
- On-tree audit: green — `check-isa x86_32: kernel and 21 user ELFs are
  486-clean`, exit 0.
- Poisoned-build trial, measured deviation from the plan's recipe: neither
  `RUSTFLAGS=-C target-cpu=i686` nor `-C target-feature=+cmov` produces `cmov`
  here. Worse-and-better: `RUSTFLAGS` *replaces* the root `.cargo/config.toml`
  `[target.rosx-i686-user] rustflags` (`-Tlinker.ld --pie`), so an exported
  `RUSTFLAGS` links a degenerate, `.text`-less ELF instead of poisoning codegen
  — an operational trap worth knowing (restore with a flagless rebuild), and
  proof that stray CI `RUSTFLAGS` cannot silently break the pin.
  The red signal was therefore demonstrated at the artifact level: a copy of
  `pi` with `f3 0f 44 c1` patched over a `0x90` run in `.text` (objdump
  decoded `repz cmove %ecx,%eax`) made the audit exit 1 naming
  `pi: cmove x1`; restoring the original file made it green again. The
  prefix-stripping path (`repz` → `cmove`) exercised end to end.

## M4 — mmap-less memory detection (`c12c2b5`)

- New `arch/x86-generic/src/multiboot.rs`: Multiboot v1 info decode owning its
  own `BootMemory`/`MemoryRegion` types (deliberately kernel-free: linking
  `kernel` into the host test harness collides with std's
  `alloc_error_handler`, so the decoder keeps zero kernel dependency and
  `arch/x86_32/src/main.rs` adapts regions into `MemoryBlocks`).
- Semantics per plan §6: bit 6 → mmap walk (stride `size + 4`, available-only,
  usize-representable); bit 0 only → `[0, mem_lower KiB)` + `[1 MiB, 1 MiB +
  mem_upper KiB)`; neither → no regions (no invented defaults). mmap wins when
  both flags are set.
- Host unit matrix (`cargo test -p x86-generic`): 26 green (9 new multiboot
  tests — available filtering, stride, empty/truncated buffer, flag precedence,
  zero-size drops, absent flags, malformed entry types).
- QEMU boot after the change: `-cpu 486` reaches `rose>`; `[MEMORY]` banner
  parses the mmap path (Region 0x219be0-0x7fe0000, Total 125 MB), BULK
  self-test green.
- Full x86_32 integration suite re-run: green (M2's run post-dates the M4 tree:
  recorded above covers both).
- The mem_upper fallback path itself stays **unverified** in QEMU (QEMU always
  supplies mmap); routed to M5 checklist item 1.
