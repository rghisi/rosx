# Kernel-hosted services and the ROM

## Invariants

- `kstatsd` runs as a kernel `FunctionTask` calling `IpcManager` directly; its `ProcessTable` reply rides the IPC data family and snapshots the task arena and per-group memory under one `IrqCell` section.
- The wire contract for kstats lives only in `system::kstats`; user-space clients own rendering.
- The ROM is an immutable image exposed through the opaque `RomMap`/`RomRelease` syscalls; its RAM stays a held block until `init` releases it after bootstrap. It is never a VFS volume and `init` is its only user-space reader.
- The ROM ships as the file `INITRD.BIN` in the boot volume's root directory: stage2 loads it into low memory, reports it through BootInfo, and the kernel embeds no program bytes. The kernel parses the image itself (`platform::bootinfo::initrd()` → `rom::validate()`) and boots `init` from it; a missing, refused, or malformed image, or one without `init`, panics naming each case.
- Both ports pack `BOOTSTRAP_APPS` into the ROM: the six bootstrap services, the shell, and `init` itself — what a bring-up needs before `/` exists, with nothing extra.

## Design

Kernel-hosted IPC services — `kstatsd` is the first: kernel code runs a service loop as a `FunctionTask` (launched by each arch at boot), calling `IpcManager` directly and blocking on futures via `Kernel::wait`. Two read-only operations share the `"KSTATSD"` binding: `MemorySnapshot` (op 0) answers in the 60-byte message; `ProcessTable` (op 1) rides the IPC data family — the reply message carries a data token (`system::ipc::encode_data_token`) and the table blob is a versioned fixed-stride buffer (`system::kstats::encode_process_table` / `decode_process_entry`), because a process list never fits 60 bytes. kstatsd snapshots the live task arena and per-group memory under one `IrqCell` section (the timer IRQ's resched path mutably borrows the task manager, so an unguarded walk would panic), then joins them: one row per loaded-image group, `pid` = the monotonic never-reused `GroupId`, one thread rolled up to the group's most-active state, memory = `MemoryManager::group_bytes` (that group's `Group` + `Stack` blocks). Metrics and identity stay domain-owned (`MemoryManager::stats`/`group_bytes`, `TaskManager::snapshot_processes`); the wire contract lives only in `system::kstats`; user-space clients (`mem`, `ps`) own rendering.

`rom/` — boot-registered immutable ROM image with a kernel-owned lifecycle `Held → Mapped(owner group) → Released` (`Lifecycle` in `kernel/src/rom.rs`, mechanism in `docs/rationale/rom-map-release.md`): `RomMap` hands one group a `RomRef` alias of the image and re-maps only for that group; `RomRelease`, owner-only and once, returns the image's held memory block to the allocator and prints `[ROM] released addr=… bytes=…`; after that `image()` serves no bytes. The kernel stays VFS-agnostic and the ROM is never a VFS volume — `init` is its only user-space reader: `usrlib`'s `RomView` borrows the mapped bytes and consumes itself on `release`, so `init` resolves every `rom:` plan token and the shell fallback zero-copy and releases the RAM at the end of its own control flow. The image arrives on the boot volume as `INITRD.BIN` (the kernel's `include_bytes!` era ended with `plans/rom-as-initrd.md`); the kernel's own boot-time reads go through `rom::program()` / `rom::validate()` over the `BootInfo` initrd slice. The roster is per-arch (`ArchSpec.rom_apps`) and both ports pack `BOOTSTRAP_APPS`. Its roster names stay underscore-free (open work: `docs/todo/rom-app-names-revert-underscore-free.md`).
