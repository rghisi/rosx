# Boot media, QEMU wiring and the integration harness

## Invariants

- Both ports boot the same plan from a FAT boot disk at IDE index 0 (`ata0d0`, slice `ata0d0p0`); the persistent host disk is `ata0d1`.
- The boot medium **is** that disk on both ports: stage1 at LBA 0, the `ROS2` stage2 blob at LBA 8 (stage2-32 on x86_32, stage2-64 on x86_64), a bootable FAT16 slice at LBA 2048, `KERNEL.ELF` at the volume root; stage banners share the 0xe9 debug stream with kernel output.
- The kernel's only boot entry is the chain's `BOOT_INFO_MAGIC` handoff; x86_64 enters long mode at the higher-half ELF entry inside the `0xFFFF800000000000` window (`code-model: large` — the window address is outside the 32-bit sign-extended range the kernel/medium models address through).
- Integration tests run release kernels prebuilt through `ROSX_KERNEL_ELF`; every session chain-boots a stamped full-apps master disk and disk-boots to the disk shell.
- Task stack sizes (`STACK_WORDS`) come from watermark measurements: 8192 words on x86_64, 12288 on x86_32.

## Detail

`cargo run` uses the **custom runner** (each arch directory's `.cargo/config.toml` → `./run.sh`), which invokes `arch/x86-runner`; it runs both ports from the unified boot disk and refuses by name when the disk has not been built (`cargo xtask build`). **No bootimage, no carrier.** The runner attaches it as `-drive if=none,id=rosxboot,…` + `-device ide-hd,drive=rosxboot,bus=ide.0,unit=0,bootindex=1` — boot order is a *device* property, and QEMU rejects `bootindex` inline on `-drive`.

**Unified boot disk (both ports)** — `cargo xtask build` writes `target/rosx-boot-disk.img` (x86_64) / `target/rosx-i486-boot-disk.img` (x86_32): a 64 MiB image whose MBR carries one bootable FAT16 slice (type 0x06, LBA 2048) with every user ELF at the root (8.3 stems enforced) plus `/boot/rom.img`; stage1's boot code at LBA 0 chain-loads the `ROS2`-headed stage2 blob at LBA 8, which loads `KERNEL.ELF` from the volume root (a deeper path like `/boot/` OOMs stage2's bump heap — `docs/todo/stage2-bump-heap-never-frees.md`) and hands off per `plans/bootloader/00-boot-abi.md`. The same recipe backs `cargo xtask image`. Stage banners (`[STAGE1]`, `[MEM]`, `[ELF]`, `[STAGE2_32]`/`[STAGE2_64]`) ride the same 0xe9 debug stream as kernel output. The by-hand harness flow needs the chain bins staged — `cargo xtask build` or `cargo xtask boot-artifacts` write `target/boot32/{stage1.bin,stage2-32.bin}` and `target/boot64/{stage1.bin,stage2-64.bin}`, and the harness errors by name when they are missing. GRUB Legacy era media is retired: the kernel's only boot entry is the chain's `BOOT_INFO_MAGIC` handoff (`docs/decisions/multiboot-era-media-retirement-trigger-fired.md`).

Both `cargo run` and `cargo xtask run` attach a persistent host-side 50 MiB IDE disk at `if=ide,index=1` (`$HOME/tmp/rosx-hdd.img`, created if missing, never truncated, survives VM restarts): `attach ATA` → `format ata0d1` → `mkdir /<dir>` → `mount ata0d1 /<dir>` → `ls /<dir>` (the mount point is a real root-volume directory that must exist before mounting; `attach ATA` registers the ATA controller with `blockd` — the single block-device provider whose namespace lives in memory, so every boot re-attaches; the persistent disk `ata0d1` has no partition table, so it stays a whole drive). The boot disk is the FAT volume `ata0d0`/`ata0d0p0`; the old `ata0d0p1`/`ata0d0p2` bootloader-slice footgun is gone. The headless integration harness keeps its own tempdir disks (`QemuSession::spawn_with_hdd_disk` for the persisting flow; `spawn_with_partitioned_hdd_disk` / `spawn_with_corrupt_partitioned_hdd_disk` hand-carve an MBR into the image first).

Target spec: `arch/x86_64/rosx.json` — bare-metal `no_std`, `code-model: large`, `build-std` = core/alloc/compiler_builtins; `arch/x86_64/linker.ld` links the kernel at `0xFFFF800000100000 AT(… - 0xFFFF800000000000)` and must collect the `.ltext/.lrodata/.ldata/.lbss` orphan families the large model emits into its AT()'d sections (an uncollected orphan lands at `p_paddr == p_vaddr` and is unloadable). `fake-kernel-64` builds with this same spec (D5).

The kernel embeds the init ELF and the ROM image that `cargo xtask build` produces under the arch's `target/<user-dir>/release/`; `arch/x86_32/build.rs` asserts both are present before compiling.

The boot plan boots from that disk: the stack comes up from ROM, `run rom:mount ata0d0p0 /` root-mounts the FAT volume, `service /randomd|/echo|/pong …` start **from the mounted volume**, and `exec /shell` hands over to the shell **loaded from disk**; when the disk or its binaries are missing the service steps log `not available` and the plan's last step (`exec rom:shell`) lands on the ROM shell instead. The ROM carries only the bootstrap set (`BOOTSTRAP_APPS` in `xtask/src/arch.rs`: atad, blockd, attach, mount, vfsd, inputd, ps2d, shell — the `rom:` tokens plus the console stack) on both ports; both ports run the identical plan on their own unified disk.

Integration tests run with `ROSX_ARCH=<arch> cargo test -p tests-integration -- --test-threads=1`; sessions on both arches chain-boot a per-session master — `tests_integration::fat_disk` builds it (rxpart-stamped MBR + mtools, all ELFs found in the user release dir, stage1/`ROS2` chain of the current arch, `KERNEL.ELF` at the volume root) and `spawn_with_master_disk` copies the caller's image into the session tempdir **before** stamping it, so built artifacts are never mutated; host-side readers (`read_file_from_image`) take the volume offset from the image's own MBR instead of assuming one. The ata suites keep their second-drive topology on top. `ipc_vfs` stays x86_64-only, `disk_boot` is x86_32-only (root mount, disk-shell hand-off, ROM fallback, and a test that boots the real `target/rosx-i486-boot-disk.img` when `cargo xtask build` produced it); `kstats_mem` runs unguarded on both arches (the wake-path race is fixed — `plans/x86_32-wake-race.md`); the `fsbench` integration test is `#[ignore]`d like the other benchmark tests — CI never runs benchmarks, and full-phase `fsbench` stays manual anyway until `plans/ipc-volume-wedge.md` is fixed, because sustained IPC volume kills the guest silently.

Task stacks (`STACK_WORDS` in `kernel/src/task_stack.rs`) are sized from watermark measurements: 8192 words on x86_64, 12288 on x86_32 — the nested `vfsd`→`atad` format chain has a fixed depth of ~35 KiB (much of it the 4 KiB IPC receive chunks). The x86_32 chain measures nearly the same byte depth as 64-bit: the stack is dominated by fixed-size buffers, not register frames.
