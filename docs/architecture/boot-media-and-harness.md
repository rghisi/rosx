# Boot media, QEMU wiring and the integration harness

## Invariants

- Both ports boot the same plan from a FAT boot disk at IDE index 0 (`ata0d0`, slice `ata0d0p0`); the persistent host disk is `ata0d1`.
- The x86_64 BIOS carrier rides the secondary IDE bus so it never enters the guest block namespace.
- Integration tests run release kernels prebuilt through `ROSX_KERNEL_ELF`; every session attaches a full-apps FAT master and disk-boots to the disk shell.
- Task stack sizes (`STACK_WORDS`) come from watermark measurements: 8192 words on x86_64, 12288 on x86_32.

## Detail

`cargo run` uses the **custom runner** (`.cargo/config.toml` → `./run.sh`), which invokes `arch/x86-runner` to make a BIOS disk image with the `bootloader` crate's `BiosBoot` (attached on the **secondary** IDE bus with `bootindex`, so the kernel is still loaded via BIOS but the carrier never enters the guest namespace), then starts `qemu-system-x86_64`. **Not bootimage.** The `bootloader` crate's stages honor the BIOS-supplied drive number end to end, so the carrier works from any IDE slot.

**FAT boot disk** — `cargo xtask build` (x86_64) also writes `target/rosx-boot-disk.img` (host `mformat`/`mmd`/`mcopy` from mtools), the same recipe as x86_32: a 64 MiB image whose MBR (stamped with `rxpart::mbr::encode_mbr`) carries one bootable FAT16 slice (type 0x06, LBA 63) organized by the `system::boot_disk` taxonomy: `/bin` (17 tools), `/games`, `/tests`, `/bench`, `/stress`, `/srv` (11 daemons) and `/boot` with `init` plus `kernel.elf` and `rom.img`. Both `cargo run` (when the image is present) and `cargo xtask run` attach it at `if=ide,index=0`, so the curated namespace is `ata0d0` with slice `ata0d0p0`; the on-disk `kernel.elf`/`rom.img` are forward-looking artifacts for a real GRUB boot, not mechanisms (the kernel uses its embedded ROM and its BIOS carrier).

Both `cargo run` and `cargo xtask run` attach a persistent host-side 50 MiB IDE disk at `if=ide,index=1` (`$HOME/tmp/rosx-hdd.img`, created if missing, never truncated, survives VM restarts): `attach ATA` → `format ata0d1` → `mkdir /<dir>` → `mount ata0d1 /<dir>` → `ls /<dir>` (the mount point is a real root-volume directory that must exist before mounting; `attach ATA` registers the ATA controller with `blockd` — the single block-device provider whose namespace lives in memory, so every boot re-attaches; the persistent disk `ata0d1` has no partition table, so it stays a whole drive). Because the kernel carrier rides the secondary bus (outside atad's primary-channel port pool), the boot disk is the FAT volume `ata0d0`/`ata0d0p0` and the old `ata0d0p1`/`ata0d0p2` bootloader-slice footgun is gone. The headless integration harness keeps its own tempdir disks (`QemuSession::spawn_with_hdd_disk` for the persisting flow; `spawn_with_partitioned_hdd_disk` / `spawn_with_corrupt_partitioned_hdd_disk` hand-carve an MBR into the image first).

Target spec: `arch/x86_64/rosx.json` — bare-metal `no_std`, `build-std` = core/alloc/compiler_builtins.

The kernel embeds the init ELF and the ROM image that `cargo xtask build x86_32` produces under `target/rosx-i486-user/release/`; `arch/x86_32/build.rs` asserts both are present before compiling.

**FAT boot disk** — `cargo xtask build x86_32` also writes `target/rosx-i486-boot-disk.img` (host `mformat`/`mmd`/`mcopy` from mtools): a 64 MiB image whose MBR (stamped with `rxpart::mbr::encode_mbr`) carries one bootable FAT16 slice (type 0x06, LBA 63) organized by the same `system::boot_disk` taxonomy — all app and directory names must fit the 8.3 stem, or the build says so — plus `/boot/kernel.elf` and `/boot/rom.img`. QEMU loads the kernel via `-kernel` and the kernel uses its embedded ROM, so the on-disk `kernel.elf`/`rom.img` are forward-looking artifacts for a real GRUB boot, not mechanisms. `cargo xtask run x86_32` attaches the image at `if=ide,index=0`, so the curated namespace is `ata0d0` with slice `ata0d0p0`; the persistent host disk stays at index=1 (`ata0d1`).

The boot plan boots from that disk: the stack comes up from ROM, `run rom:mount ata0d0p0 /` root-mounts the FAT volume, `service /srv/randomd|/srv/echo|/srv/pong …` start **from the mounted volume**, and `exec /bin/shell` hands over to the shell **loaded from disk**; when the disk or its binaries are missing the service steps log `not available` and the plan's last step (`exec rom:shell`) lands on the ROM shell instead. The ROM carries only the bootstrap set (`BOOTSTRAP_APPS` in `xtask/src/arch.rs`: atad, blockd, attach, mount, vfsd, inputd, ps2d, shell — the `rom:` tokens plus the console stack) on both ports; x86_64 runs the identical plan on its own `target/rosx-boot-disk.img`.

Integration tests run on x86_32 with `ROSX_ARCH=x86_32 cargo test -p tests-integration -- --test-threads=1`; the harness boots the kernel ELF directly, and every session on both arches attaches a **full-apps FAT master** (`tests_integration::fat_disk` — rxpart-stamped MBR + mtools, the `system::boot_disk` app taxonomy staged into its directories), so sessions disk-boot to the disk shell and resolve every CLI through the root mount and the shell search path; the ata suites keep their second-drive topology on top. `ipc_vfs` and `ata_env_spike` stay x86_64-only, `disk_boot` is x86_32-only (root mount, disk-shell hand-off, ROM fallback, and a test that boots the real `target/rosx-i486-boot-disk.img` when `cargo xtask build` produced it); `kstats_mem` runs unguarded on both arches (the wake-path race is fixed — `plans/x86_32-wake-race.md`); the `fsbench` integration test is `#[ignore]`d like the other benchmark tests — CI never runs benchmarks, and full-phase `fsbench` stays manual anyway until `plans/ipc-volume-wedge.md` is fixed, because sustained IPC volume kills the guest silently.

Task stacks (`STACK_WORDS` in `kernel/src/task_stack.rs`) are sized from watermark measurements: 8192 words on x86_64, 12288 on x86_32 — the nested `vfsd`→`atad` format chain has a fixed depth of ~35 KiB (much of it the 4 KiB IPC receive chunks). The x86_32 chain measures nearly the same byte depth as 64-bit: the stack is dominated by fixed-size buffers, not register frames.
