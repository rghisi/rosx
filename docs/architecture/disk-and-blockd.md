# Disk and the block namespace

## Invariants

- ATA command semantics live in `atad`; the kernel contributes only the mediated port capability, won through `PortAcquire` (exclusive across tasks, pool-bounded, idempotent for the holder, released on `PortRelease` or at task termination).
- `blockd` is the single block-device provider; consumers such as `vfsd` dial `"BLOCKD"` only, and every disk or slice is named by a globally unique stable name (`ata0d0`, `ata0d0p0`).
- Registering a provider reads sector 0 of each drive and asks `rxpart` for the exposure verdict: a valid MBR exposes its slices and hides the whole drive; a corrupt table exposes the whole drive as `Corrupt`; otherwise the whole drive is exposed `Clean`.
- Register is the rescan; there is no `Rescan` opcode.
- A provider fault during the sector-0 read fails `Register`; nothing is exposed with a fabricated state.

## Design

Disk architecture — ATA command semantics live in the user-space `ATAD` daemon (`atad`) over `ata-protocol`; the kernel contributes only the mediated port capability: the arch port declares the grantable ranges on `KConfig.port_pool` (x86: `x86_generic::port::X86_PORT_POOL` = 0x1F0–0x1F7, 0x3F6, 0x280–0x3FF, 0xCF8–0xCFF, 0xC000–0xFFFF) and a driver wins them at startup through the `PortAcquire` syscall — exclusive across tasks (`PortRangeBusy`), pool-bounded (`PortRangeNotInPool`), idempotent for the holder, surrendered by `PortRelease` or automatically at task termination; `atad` acquires both ranges before probing and exits with a failure status if refused. v1 polls; IRQ14 delivery is the v2 event path. Presence discipline (measured on a VLSI 82C480 controller that does not float an absent slave — status reads 0x00, not 0xFF — and on QEMU): `atad` applies the DrivePresent rule (`!BSY && !DRDY` = nothing attached) only while waiting for DRQ, where a phantom's IDENTIFY never raises it and the `NotFound` verdict is immediate with no DRQ budget burned; during soft-reset and select windows a present drive legitimately reads `!BSY && !DRDY`, so the rule must never fire there. On the same `ATA` binding `atad` also serves the generic **block family** of `block-protocol` (requests 0x20–0x2F, replies 0x30–0x3F, disjoint from the ata opcodes, decoded by band): `Probe` declares the device's honest geometry (atad declares 512-byte blocks = its sectors) plus a model/firmware description, `Read`/`Write` are block-addressed with a transfer count, `Flush` flushes the drive. The vendor face keeps sector truth for the `ata` CLI; `vfsd` speaks only the block family. **Block namespace:** the user-space `BLOCKD` daemon (`blockd`) is the single block-device provider: `Register <service>` binds a provider slot (`ata` → `ata0`), discovers its drives (probe device `0`, walk until `NotFound`, cap 8), and republishes them under globally unique stable names — `ata0d0`, `ata0d1`, … — where the `d`-form is reserved for discovered device leaves so service aliases can never collide with them. Client traffic carries one base-relative block number: blockd range-checks against `base + len`, forwards `base + block` to the slot's provider, and rewrites the device field on replies; `List`/`Probe` are served from the namespace table, only read/write/flush reach the provider. A re-`Register` refreshes the provider in place (same slot, only that slot's entries torn down and re-probed) and is not `Busy`; entries carry `kind` (`Disk`/`Partition`) and `state` (`Clean`/`Corrupt`). **Curation:** registering a provider reads each discovered drive's sector 0 through the provider and asks `rxpart` (`fs/partition`) for the exposure verdict: a valid MBR with at least one supported entry means the table wins — the whole drive does not enter the namespace and every supported slot becomes a slice device `ata{c}d{d}p{slot}` (zero-based true MBR entry index, holes skipped, `state=Clean`, `base=start_lba`, `len=sector_count`), so whole-disk/slice overlap is impossible by construction and no runtime overlap guard exists anywhere; no table, an empty table, or a table whose only entries are refused containers (0x05/0x0F/0x85, GPT-protective 0xEE) exposes the whole drive `Clean` with the refused types named in the description; a corrupt table exposes the whole drive as `Corrupt` — expose-on-corrupt keeps the rescue path open because the OS has no table writer. A provider fault during the sector-0 read fails `Register` exactly like a probe fault — nothing is exposed with a fabricated state. Registration logs one `DriveVerdict` line per drive (whole/partitions, refused container bytes verbatim) so every exposure decision is visible at `attach <service>` time. Vocabulary: a controller is `ata0`, a disk `ata0d1`, a slice `ata0d1p1`; `volume` names a mounted filesystem (rxfs or rxfat) and is never a partition. Staleness is the contract: re-`Register` re-reads sector 0 — Register *is* the rescan, there is no `Rescan` opcode. The vendor `ATA` face is the sharp knife: the `ata` CLI reads and writes whole-drive sectors past curation (diagnostic territory), so the blockd view and the `ata` view are complementary, not contradictory; the OS-side table authoring tool (`fdisk`-lite, a vendor-face client) stays its own plan with a busy/mounted handshake. blockd holds every provider connection for the whole boot (one per source, owned by the daemon task), which is why the VFS wire never carries service names. Norm, not enforcement: direct `"ATA"` dials stay available for diagnostics — the `ata` CLI keeps the vendor face — while `vfsd` and any future block consumer dial `"BLOCKD"` only. The `attach` CLI is blockd's thin client: bare lists the namespace grouped by source, `attach <service>` registers a controller; VFS opcodes 13 and 14 are reserved and unused.
