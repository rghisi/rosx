# VFS

## Invariants

- `vfsd` owns no block storage; the mount table is the root, and the kernel ROM never enters the VFS.
- `vfsd` is coupled to the `fs/core` `Engine` treaty; dispatch, routing and Busy guards never learn which engine serves a slot, and a cross-engine handle is `BadHandle`.
- The wire carries absolute paths; routing takes a path's first segment against the mount table, and the empty-named `/` mount swallows every otherwise-unclaimed path.
- A mount point must exist as a directory under a mounted `/`; a mounted device cannot be formatted or mounted twice, and a live mount point is `NotPermitted` to `rm`/`rmdir`.
- `MOUNT` auto-detects the engine (rxfs magic first, then a boot sector `rxfat` accepts); `format` stays rxfs-only.
- Ownership and open modes are enforced daemon-side; `sync()` commits after every mutating request.

## Design

VFS architecture — the `VFS` daemon (`vfsd`) owns no block storage: it starts with an empty namespace and the mount table is the root. It is coupled to the `fs/core` `Engine` interface, not to a concrete filesystem: `VfsStore<D: BlockDevice>` holds mounted volumes as a `Vec<MountedVolume<D>>` table whose engine slot is a `MountedEngine<D>` — the enum `Rxfs(FileSystem<D>) | Fat(rxfat::FileSystem<RemoteWindow>)` implementing the `Engine` treaty itself, so dispatch, routing and Busy guards never learn which engine serves a slot (production `ActiveStore = VfsStore<RemoteWindow>`); every operation flows through the trait (method-call syntax, no inherent engine call). A cross-engine handle misuse (an rxfs handle against a fat slot or the reverse) is `BadHandle`. The kernel ROM never enters the VFS: `init` reads the ROM image itself through its mapped `RomView` (`RomMap`/`RomRelease`), and `vfsd` answers nothing before a mount. The wire carries paths: `valid_path` is always absolute — `/` itself (the root) or one or more `valid_name` segments joined by `/` bounded by the 60-byte frame — and routing looks a path's first segment up in the mount table — paths under a live named mount, bare or nested, go to that volume, the empty-named `/` mount swallows every otherwise-unclaimed path, everything else is `NotFound`. The root `/` itself always exists in the table: `stat` answers a directory of size 0, `list` answers the sorted named-mount names, and every file operation below an unmounted root stays `NotFound`. Listing is one operation (`LIST`, number 8) following the same routing; opcode 6 is reserved and unused. A read-only `stat` query answers path → kind + size straight from `Engine::lookup` (zero open slots), and the shell launcher's file read is size-bounded so a mid-launch mutated image fails as "truncated" instead of executing. Ownership and open modes are enforced daemon-side (no engine knows either); `sync()` commits after every mutating request. `MKDIR`/`RMDIR` ride the wire onto `Engine::mkdir/rmdir`, and `NotDirectory`/`IsADirectory`/`DirectoryNotEmpty` are error bytes 10–12. **Device addressing:** `FORMAT`/`MOUNT` carry `blockd` device names — `vfsd` dials `"BLOCKD"` over `block-protocol::manager::client::Manager`, probes to fail early, rejects geometries the engine cannot adapt (`VfsError::Unsupported`, error byte 13) and owns no registry: opcodes 13 and 14 are reserved and no VFS wire frame names a service. `format <device>`/`mount <device> <dir>` re-dial and re-probe fresh (unknown device → `NotFound` from blockd's `Probe`) and drive the volume through `RemoteWindow` (`apps/vfsd/src/blk.rs`), the `fs/core` `BlockDevice` adapter that maps one engine-unit block to `unit_bytes / declared_block_size` contiguous device blocks in one request — a 4 KiB window for rxfs, the volume's own sector size for FAT — so any mix of engines and device geometries mounts side by side, and answers `Unsupported`-sized geometries honestly. **Disk volumes:** a mount point is a directory that exists under a mounted `/` (the Linux rule): the caller `mkdir`s it through the live namespace first and `mount` validates it through the same routing (must exist and be a directory), and `rm`/`rmdir` refuse a live mount point as `NotPermitted`. The mount destination may also be `/` — the one mount point the VFS always has: `valid_mount_dir` accepts the root and the table records it as the empty-named entry. Routing stays first-segment: a named mount wins when the path's head equals its name, and the root mount swallows every other path — after a root mount unclaimed paths resolve on that volume and unknown prefixes answer from it rather than `NotFound`; mount-point validation for a later `MOUNT` flows through the same routing, so a named mount can be established at a directory that lives on the root-mounted volume. `/` itself stays `NotPermitted` to `rm`/`rmdir` under every configuration. The Busy guards: the mount table refuses a mounted device for `format` or a second mount point — blockd would happily hand out a second connection to the same disk, so this local guard is what keeps one disk from mounting twice — and mount names stay unique: a mounted device cannot be reformatted; unformatted/corrupt volume → `NotFormatted`. MOUNT auto-detects the engine before constructing it: the rxfs `FS_MAGIC` at superblock block 1 wins, else a boot sector that `rxfat`'s total parser accepts mounts FAT, neither → `NotFormatted` — the mount CLI and the wire never name a filesystem type, and `format` stays rxfs-only. Open files carry the table slot and the engine `MountHandle` of the volume they live on, and read/write/close dispatch through them. The daemon holds no mount name: "hdd" is pure caller convention.
